# Definition of Ready and Definition of Done

These are adaptable checklists. Apply only relevant items and make mandatory gates explicit for the product.

## Definition of Ready (for a feature or implementation group)

- [ ] User/business problem and intended outcome are understood.
- [ ] Scope and explicit exclusions are clear.
- [ ] Acceptance criteria are observable and testable.
- [ ] Relevant NFRs and constraints are identified.
- [ ] Dependencies, interfaces, and affected components are known.
- [ ] UX/design and technical decisions are sufficient for the next step.
- [ ] Risks, assumptions, and open questions are visible.
- [ ] Owner and priority are assigned.
- [ ] Test approach and validation environment are understood.
- [ ] Work is sized or uncertainty is explicitly planned for discovery.

## Definition of Done (for an implementation increment)

- [ ] Agreed scope is implemented; exclusions remain explicit.
- [ ] Code follows agreed standards and is reviewed.
- [ ] Required automated checks and tests pass.
- [ ] Group-level acceptance and relevant regression checks pass.
- [ ] Security, privacy, accessibility, and performance checks are completed where applicable.
- [ ] Defects are resolved or explicitly accepted by the authorized owner.
- [ ] Documentation, API contracts, and operational notes are updated.
- [ ] Monitoring, alerts, and support considerations are addressed where applicable.
- [ ] Data/configuration/deployment changes are documented and safe.
- [ ] Release and rollback/mitigation approach is known.
- [ ] Product owner or delegate accepts the outcome.

## Do not misuse the checklists

A checked box is not evidence by itself. Link to actual test results, review records, decisions, or acceptance evidence for material items. Do not mark an item complete when it is not applicable without recording that judgment where needed.
