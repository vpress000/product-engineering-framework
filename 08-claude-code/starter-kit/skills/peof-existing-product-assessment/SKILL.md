# Existing Product Assessment Workflow

1. Confirm authorization, repositories/systems in scope, protected paths, active releases, and read-only boundaries.
2. Inventory existing instructions, requirements, architecture, source code, tests, CI/CD, security controls, operations, and team practices.
3. Establish source-of-truth and artifact freshness; compare documentation with implementation where evidence allows.
4. Identify strengths to preserve, conflicts, duplicate artifacts, risks, gaps, and unknowns.
5. Classify each artifact/practice as retain, improve, consolidate, replace, archive, create, or defer.
6. Build a target-state map and prioritized adoption/modernization backlog.
7. Define pilot, migration waves, owners, dependencies, validation, communications, and rollback/containment.
8. Present exact changes and ask for approval before writing or migrating.

## Boundaries
No rewrite by default. No destructive or bulk changes without explicit approval. Do not migrate secrets, production credentials, or unnecessary personal data into documents or AI context. Do not silently supersede a current source of truth.

## Output
Provide current-state summary, evidence inventory, strengths, maturity/risk gaps, artifact mapping, target model, phased plan, risks, and approvals required.
